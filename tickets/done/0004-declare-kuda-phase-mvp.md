# kuda のフェーズ宣言を MVP 期として明示する

## 内容

このリポジトリには CLAUDE.md が存在しない。kuda の規約では宣言が無いリポジトリは issue 期として扱われるため、現状は宣言せずに issue 期に置かれている。

issue 期は「公開面の定義が台帳に書かれており、かつ `要精査` が0本」——すなわち全モジュールについて何を約束にすべきか一度は決め終えた状態を意味する。このリポジトリは `docs/guarantees.md` を持たず、その判断を一度も通していない。実態は MVP 期であり、宣言と実態が食い違っている。

CLAUDE.md を新規作成し、フェーズ宣言の1行を置いてこの食い違いを解消する。台帳の敷設は後続のチケットで行うが、敷設より先にフェーズを実態へ合わせる——宣言が issue 期のまま台帳を敷くと、`要精査` を持てないフェーズの下で「まだ何を約束にすべきか決められない」行の置き場が無くなる。

CLAUDE.md に置くのはフェーズ宣言の1行だけとする。常時ロードされる文書であり、全セッションに維持コストが課金されるため、この時点で他の規約を書き込まない。

### やらないこと

- `docs/guarantees.md` の敷設（後続チケット）
- `docs/conventions.md` の作成（必要が出た時点で別チケット）
- コーディング規約・環境情報など、フェーズ宣言以外の内容を CLAUDE.md に書くこと

## 保証

### 新たに宣言する保証

- なし。フェーズ宣言はワークフローの設定であって、このリポジトリが外部へ提供する振る舞いではない。台帳はまだ存在せず、公開面の定義もこのチケットでは立てない

### 維持する保証

- なし。`docs/guarantees.md` が未敷設であり、維持すべき台帳の行が存在しない

### 廃止する保証

- なし。既存の約束を取り下げる変更ではない
