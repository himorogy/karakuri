# 保証台帳を新設し、公開面の定義と境界宣言を敷く

## 内容

この変更は保証台帳の敷設を配布単位で分割した束の1枚目である。

**束の全体像。** このリポジトリは複数の配布単位を通じて外部へ公開面を提供しているが、これまで保証台帳を持たなかった。既存の18本のテストが固定している振る舞いを抽出し、外から観測できる語彙の宣言文として台帳へ移す。抽出はテストのラベルではなくテスト本体を読んで行った。

**家族一覧（順序依存あり）:** 0005 分母と境界宣言 → 0006 env-guard → 0007 egress-guard → 0008 prod 起動経路 → 0009 認証と出荷物検査 → 0010 ホスト入口 → 0011 ホスト注入・broker・loopback。

**不変条件:** 台帳を変更する経路はチケットのみ（候補層 `docs/guarantee-candidates/` の追加・削除だけが例外）。索引の粒度はテストファイル単位に固定する。

**この枚の役割。** `docs/guarantees.md` を新規作成し、末尾の境界宣言だけを敷く。保証の行は1本も書かない——以降の各枚が、この枚が定めた分母のうち自分の配布単位の節を足していく。分母を先に確定させるのは、後続の枚が「自分の担当範囲がどこまでか」を分母から読めるようにするためであり、分母を最後に書くと途中の枚は範囲を持たずに保証を並べることになる。

境界宣言に書くのは4つ。

1. **免責** — この台帳に載っていない振る舞いは約束ではなく、予告なく変わる。網羅の宣言ではない
2. **公開面の定義（分母）** — この台帳が対象とする面の列挙。配布単位で束ね、その下にエントリポイントを並べる
3. **索引の粒度** — 出典はテストファイル単位とする。テスト名まで下ろすのは、安全性・不可逆性に関わる行に限る
4. **起源の粒度** — 裁可済み節と未検証の約束が持つ起源 `(<チケット id>, <統合の参照>)` は、行ごとではなくセクション単位で置く

3 を宣言するのは、乖離監査（`kuda:audit` の B-1）がどの粒度で突き合わせるかを台帳自身が決める必要があるため。このリポジトリのテストランナーは各テストファイルが検査ラベルを自前で定義しており、成功は `  ok   <ラベル>` を stdout に、失敗は `  FAIL <ラベル>` を stderr に出す。ラベル単位の機械照合は可能だが、ラベル総数が800を超え、共通ランナーを持たないため対応表を手で維持できない。腐った索引は監査を通してしまうので、ファイル単位を採る。

4 を宣言するのは、規範が「各行が起源を持つ」と定めているのに対し、このリポジトリではセクション単位を採るという逸脱を明示しておくため。規範の書き方は増分育成——行が1本ずつ増えていく運用——を想定していると読める。敷設では1枚のチケットが複数のセクションを丸ごと足すので、行ごとに置くと同一の起源が数十回繰り返されて台帳が読めなくなる。以後、既存のセクションへ行を足すチケットは、その行に個別の起源を付ける。

代償として、既存のセクションへ黙って挿入された行を起源の形式検査で拾えなくなる。規範はこの検査を「台帳自体の無断改変に対する唯一の機械的な足がかり」と位置づけているので、セクション単位に降ろすぶん、この層の防御はレビューに寄る。読みやすさとの取引としてこれを選ぶ。

### 候補層へ置くもの

候補層（`docs/guarantee-candidates/0005-ledger-scaffold.md`）は拘束力ゼロの層であり、targets には含めない（機械ゲートの除外パス）。この枚の実装と同時に置く。

- `要精査` 配布単位 E（`devcontainer-base` イメージと `examples/` の雛形3本）。公開面と判定したが、対応するテストを持たず、何を約束にすべきかも定めていない
- `テスト未作成` 差し替えた broker 環境コマンドが `NAME=VALUE` の形でない行を出したときに、その語がコマンドとして実行されない
- `テスト未作成` 取得した GitHub の meta レンジは staging ではなく有効なセットへ直接足されるため、バンドルの選択を外して再実行したときに以前のレンジがセットから消える
- `テスト未作成` イメージへ焼き込まれるコードのうち、運用者向けに出力する文字列は、参照先のパスを伴っていても記号を含まない（現在の検査は他の2本の部分集合になっており、コメントが宣言しているこの禁止を実際には課していない）
- `テスト未作成` 配布される commit 前フックが、イメージの `core.hooksPath` 経由で実際に起動する（現在のテストはフックを直接実行しており、本番の配線を通らない）
- `テスト未作成` egress の自己検証で、生存判定を飛ばした実行でも遮断側の検査（外部 DNS の遮断・未許可先の遮断）は飛ばされずに走る
- `テスト未作成` egress の自己検証は、遮断先の候補が1つも解決しなかった場合に「すべて許可済みだった」と報告しない（現在は両者を区別せず後者の文言を出す）
- `テスト未作成` `allowHostPorts` を指定した実行で、ホスト名が解決しなかった場合に警告が出る（仕様は警告を出すと書いているが、実装にその分岐が無い）
